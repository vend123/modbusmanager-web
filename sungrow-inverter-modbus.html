Sungrow Inverter Modbus Register Map

How to read a Sungrow SG string inverter or SH hybrid over Modbus TCP or RS485. Sungrow's protocol has three habits that trip up almost everyone the first time: the documented address is one more than the one you request, measurements are input registers (FC04) while the same numbers under FC03 mean something else, and 32-bit values come low word first. This page covers all three, then the registers you need for monitoring. SMA, Fronius or SolarEdge instead? They use SunSpec.

Opening Modbus TCP on a WiNet-S: in the WiNet-S web page or the iSolarCloud app, under the communication module's settings, set the Modbus TCP (port 502) option to open, and either turn the IP whitelist off or add your PC's address. Update the dongle firmware if the option is missing. Sungrow's own WiNet-S manual does not describe this; the steps come from installers and integrators, so the menu wording may differ on your firmware.

The Three Rules

1. Request the documented address minus one

Sungrow's tables list addresses such as 5000, and the document itself says to subtract 1: register 5000 goes on the wire as 4999 (0x1387). Its worked example reads 01 04 13 87 00 02 to get documented registers 5000–5001. The addresses are plain numbers, not 3xxxx/4xxxx notation. If your tool adds the offset itself (1-based addressing), enter the document's number unchanged.

2. Measurements are input registers (FC04)

Sungrow uses both register types, and they reuse the same numbers. The running data — power, voltages, yield, state — is in the input registers, read with FC04 ("3x" in the document). The holding registers (FC03 to read, FC06/FC16 to write) are settings. At documented 5000–5005 the holding registers hold the system clock, so an FC03 read of "5000" returns the current year, not the device type.

3. 32-bit values are low word first

For U32/S32 values Sungrow sends the low word at the lower address (bytes within each word stay big-endian). Sungrow's own example: the two registers 0x2BF6, 0x000B combine to 0x000B2BF6 = 732 150. Read as high-word-first, the totals are wildly wrong.

Not on this model: a register a model does not have reads 0xFFFF (U16), 0x7FFF (S16), 0xFFFFFFFF or 0x7FFFFFFF (32-bit) — for example MPPT3 on a two-MPPT inverter. Treat those as "not available", not as data.

SH Hybrid Inverters

The SH series has its own protocol document, and it is not a superset of the SG map. On SH, 5022–5030 is reserved (no phase currents or active power there), and documented 5004 is total output energy in 0.1 kWh, including battery discharge. Registers 5000–5003, 5008, 5011–5021 and 5033–5036 mean the same as on SG. The hybrid data sits at 13000 and up:

Common Mistakes

  • Every value looks shifted: the documented address was requested without subtracting 1 — you are reading the next register.
  • "Device type" reads 2026: FC03 was used. The device type is an input register: FC04.
  • Total yield is a nonsense number: the 32-bit pair was combined high word first. Sungrow sends the low word first.
  • 65535 or 32767 on some channels: the model does not have that input (e.g. MPPT3) — not a fault.
  • SG addresses on an SH hybrid: 5022–5032 is reserved on SH; use the 13000 block.
  • No connection to the WiNet-S: Modbus TCP not opened, or the whitelist excludes your PC.
  • Fault code reads a stale value: 5045 only means something while the work state is Fault (0x5500) or Alarm run (0x9100).

Frequently Asked Questions

Why are all my Sungrow values off by one register?

Sungrow's documents list addresses one higher than the protocol address. Subtract 1 from every documented address: documented 5031 (total active power) is requested as 5030. A tool with 1-based addressing does this for you.

Should I use FC03 or FC04 for a Sungrow inverter?

FC04 (read input registers) for all running data. FC03 reads the holding registers, which are settings and reuse the same numbers — at 5000–5005 they are the system clock.

What is the Modbus TCP port and unit ID?

Port 502, on inverters with a built-in Ethernet port and through a WiNet-S/S2 dongle once Modbus TCP is opened on it. Unit ID 1 is what works in practice; Sungrow's documents state the RS485 address (default 1 on SH) but not a separate TCP unit ID.

Why does the total yield read a huge or tiny number?

Sungrow sends 32-bit values low word first. Combine the second register as the high word: value = second × 65536 + first.

Does the SG register map work for SH hybrids?

Partly. The PV, temperature and voltage registers match, but 5022–5030 is reserved on SH and the hybrid values (battery, load, export, meter) are in the 13000 block and around 5214 and 5601.
