Victron Cerbo GX Modbus TCP: Unit-IDs, Registers and Scale Factors

A Victron GX device — Cerbo GX, Color Control GX, Venus GX or the GX built into a MultiPlus-II — is a Modbus TCP gateway to everything connected to it: inverter/chargers, solar chargers, batteries, meters. The Unit-ID picks the device, the register picks the value, and nearly every first attempt fails on the Unit-ID. This page covers enabling the server, the Unit-IDs, the system registers, the scale factors and the error codes, from Victron's own manual and register list.

Enable the Modbus TCP Server

Modbus TCP is disabled by default. On the GX go to Settings → Integrations → Modbus TCP server (on older firmware Settings → Services → Modbus-TCP) and enable it. The server listens on TCP port 502. The same menu lists Available services — every connected device with its Unit-ID — and shows the last error, which is the fastest way to see why a request failed.

Unit-ID Selects the Device

The GX answers for every device behind it; the Unit-ID in the request says which one. Victron's preferred IDs:

Unit-IDDevice
100com.victronenergy.system — the whole-system values (0 maps to the same; use 100)
227Cerbo GX VE.Bus port: MultiPlus / Quattro
228MultiPlus-II GX / EasySolar-II GX VE.Bus port
242Venus GX VE.Bus port
246Color Control GX VE.Bus port
223 / 224 / 226Cerbo GX VE.Direct ports (solar chargers, battery monitors)
225CAN-bus BMS

Since Venus OS 2.60 Unit-IDs are assigned dynamically: the table gives the preferred ones, but the Available services list on your GX is the truth. They do not change after a reboot. Units in a parallel or three-phase system are not addressed one by one — read the totals.

Error Codes

CodeMeaning on a GX
0x01Function not supported (only 3, 4, 6, 16 are)
0x02Unit-ID fine, but a requested register does not exist for that device — including a gap inside a block
0x03Invalid quantity of registers
0x0AUnit-ID in the mapping list, but no device on that port
0x0BUnit-ID not in the mapping list at all

Reading 1–100 in one go fails because registers 1 and 2 do not exist; reading 840–850 fails because 847–849 are reserved. Read gap-free blocks, as the workspace does.

Common Mistakes

  • Connection refused: the Modbus TCP server is not enabled on the GX.
  • Exception 0x0B or 0x0A: the wrong Unit-ID; check Available services.
  • Exception 0x02 on a block: the block contains a register the device does not have.
  • Battery 526 V: scale factor 10 not applied (52.6 V).
  • Inverter power ten times too small: scale 0.1, so multiply by 10.
  • Trying to write absorption voltage: configuration settings of a Multi cannot be changed over Modbus.

Step-by-Step: Reading a Cerbo GX with ModbusManager

  1. Enable the Modbus TCP server on the GX and note the Unit-IDs under Available services.
  2. In ModbusManager choose TCP, the GX's IP address, port 502.
  3. Read FC03, Unit-ID 100, address 840, quantity 7: battery voltage, current, power, SOC and state.

Frequently Asked Questions

Which Unit-ID does a Victron Cerbo GX use for system data?

Unit-ID 100 for com.victronenergy.system: battery 840–846, PV 850, grid 820–822, consumption 817–819. Unit-ID 0 maps to the same data, but Victron recommends 100.

How do I enable Modbus TCP on a Victron GX?

It is disabled by default. Enable the Modbus TCP server under Settings → Integrations (older firmware: Settings → Services). The same menu lists the Unit-ID of every connected device.

What does exception 0x0B mean from a Victron GX?

The Unit-ID is not in the GX's mapping list. 0x0A means it is mapped but no device answers on that port, and 0x02 means the Unit-ID is right but a requested register does not exist.

How are Victron Modbus values scaled?

Divide by the scale factor in Victron's register list: battery voltage 840 has factor 10 (526 = 52.6 V); VE.Bus power has factor 0.1, so the raw value is multiplied by 10.

What is the Unit-ID of the MultiPlus on a Cerbo GX?

Victron's preferred ID for the Cerbo GX VE.Bus port is 227 (CCGX 246, Venus GX 242, MultiPlus-II GX 228). Since Venus OS 2.60 IDs are assigned dynamically; check Available services on your GX.
