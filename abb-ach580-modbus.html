ABB ACH580 Modbus RTU: Registers, Setup and Why It Won't Start

The ABB ACH580 HVAC drive has a Modbus RTU slave built in — the embedded fieldbus (EFB) on terminals 29–31. The register map is ABB's standard one, but the ACH580's HVAC defaults catch people out: the drive refuses to start until DI4 is closed, Actual value 2 reads zero until you configure it, and whether a lost BMS stops the fan depends on a parameter whose default changed between manual editions. This page covers the registers, the group 58 setup, the control word and those three traps, all from ABB's firmware manual.

Connection Settings (Parameter Group 58)

The EFB is Modbus RTU only on RS-485 (the same port also speaks BACnet MS/TP and N2; 58.01 picks one). For Modbus TCP you need an option module (FMBT-21 or FENA-21) or a gateway. Wire 29 B+, 30 A- and 31 DGND on X5; the termination (S4) and bias (S5) switches are next to it — on only at the ends of the line.

Scaling of the references and actual values

The ACH580 ships in scalar motor control (99.04), so with the default type Speed or frequency both Ref1 and Act1 are a frequency: 20000 = 46.02 Frequency scaling, which is 50.00 Hz or 60.00 Hz depending on the drive's 50/60 Hz setting. Act1 = 17966 on a 50 Hz drive is 17966 × 50 / 20000 = 44.9 Hz. In vector control they become speed, with 20000 = 46.01. Negative values (two's complement) mean reverse.

Act2 reads 0 on a running drive: that is the default, not a fault. 58.29 EFB act2 type is Transparent and its source 58.32 is Not selected. Point 58.32 at a signal (or set 58.29 to a type), or simply read the parameter you want directly, as below.

Reading Any Parameter Directly

With 58.33 Addressing mode at its default Mode 0 every parameter has two addresses, so you do not have to map anything into Data I/O first:

  • 16-bit: 400000 + 100 × group + index — 01.06 is 400106 (wire 105). Scaled by the 16-bit fieldbus equivalent: for 01.06 that is 46.02 again, for 01.07 it is 46.05 (default 10000 A = 10000, i.e. whole amps).
  • 32-bit: 420000 + 200 × group + 2 × index — 01.06 is 420212 (wire 20211), two registers, low word first (58.34 LO-HI). The 32-bit scaling is fixed and finer: 100 = 1 Hz, 100 = 1 A.

Control Word: Start, Stop, Reset

ABB Drives profile, register 400001 (wire 0). Bit 10 REMOTE_CMD must be 1 for the drive to take commands from Modbus, which is why every value below has 0x400 in it. ABB's sequence for the ACH580:

The status word at 400004 (wire 3) answers: bit 0 ready to switch on, 1 ready to run, 2 running, 3 fault, 7 warning, 8 at setpoint, 9 remote. A running drive at speed under Modbus control reads 0x0337. The same bits are also readable one by one as discrete inputs (FC02, 100001…) and the control word bits as coils (FC01/FC05, 000001…); the digital inputs DI1–DI6 follow at 100033–100038.

Why the ACH580 Won't Start from Modbus

The control word is right, the status word says ready, and nothing turns. On an ACH580 it is usually one of these, in this order:

  • Warning AFEE Start interlock 1. In the HVAC default configuration 20.41 Start interlock 1 is wired to DI4 (damper end switch, safety chain). With DI4 open the drive will not start, whatever Modbus says. Read 10.02 bit 3 or warning 04.06 = 0xAFEE. Close DI4 or set 20.41 to Not used if there is no interlock.
  • Warning AFED Run permissive. 20.40 has a source that is off. Not used by default, but often set at commissioning.
  • Panel in Hand or Off. Local control from the panel always overrides the external location. Status word bit 9 (remote) is 0. Press Auto.
  • 20.01 is not Embedded fieldbus, or the reference source (28.11, or 22.11 in vector) is not EFB ref1 — the drive starts but runs to the wrong reference.
  • Bit 10 REMOTE_CMD missing: writing 0x0007 or 0x000F instead of 0x0477 / 0x047F.
  • Safe torque off open on X4 — both channels must be closed for any start.

Communication Loss: Check 58.14 on Your Drive

The current firmware manual (3AXD50000027537 Rev J, 2026) lists 58.14 Communication loss action = No action as the default: if the master stops, the drive keeps running on the last command. Older editions of the same manual list Fault, so read 58.14 on the panel rather than trusting either. When it is Fault, the drive trips with 6681 EFB comm loss after 58.16 (30 s) — but only when control or the reference is expected from the EFB. Other choices: Last speed, Speed ref safe (22.41 / 28.41), Fault always, Warning (A7CE).

Mind 58.15: with the default Cw / Ref1 / Ref2 only a write of the control word or a reference resets the timer. A BMS that starts the fan once and then only reads will, with 58.14 = Fault, trip the drive 30 s later. Write the control word cyclically (ModbusManager's periodic write does this), or set 58.15 to Any message.

Diagnostics Built into the EFB

  • Error registers 400090–400095 describe the last failed query: 400091 the function code, 400092 the error (02h value out of limits, 03h faulty index, 05h wrong data type), 400093 the register that failed, 400094 / 400095 the last good write and read. Write 1 to 400090 to clear them.
  • FC 2Bh / 0Eh Read Device Identification returns vendor "ABB", the product code and product name "ACH580" — a quick way to confirm what is on the address.
  • 58.08–58.12 on the panel count received and transmitted packets, UART errors and CRC errors; a rising CRC count means wiring or termination, not addressing.

Common Mistakes

  • Everything is one register off: 400001 was requested as address 1. The control word is wire address 0, the status word 3.
  • Frequency reads 17966 instead of 44.9: Ref1 / Act1 are in 20000 = 46.02 units, not Hz × 10.
  • Act2 is always 0: the default (Transparent, Not selected). Configure 58.29 / 58.32 or read 01.07 directly.
  • 32-bit values are huge: combined high word first. The ACH580 sends the low word first (58.34 LO-HI).
  • Exception 02 on a block that "should" exist: it crosses a parameter index that does not exist.
  • Group 58 edits ignored: no 58.06 Refresh settings and no reboot.
  • The fan stops 30 s after the BMS starts it: 58.14 = Fault and the BMS only reads (58.15 Cw / Ref1 / Ref2).

Step-by-Step: Reading an ACH580 with ModbusManager

  1. Wire a USB–RS-485 adapter to X5: 29 B+, 30 A-, 31 DGND. Termination on at the adapter end and at the last drive.
  2. Set 58.01 Modbus RTU, 58.03 the address, then 58.06 Refresh settings. Keep 19.2 kbps, 8 EVEN 1 unless the line uses something else.
  3. In ModbusManager choose RTU, the COM port, 19200 baud, Even parity, 1 stop bit.

Frequently Asked Questions

What is the Modbus address of the ACH580 status word?

Holding register 400004, which is address 3 on the wire (FC03). The control word is 400001 (address 0), the frequency reference 400002 (address 1) and Actual value 1 400005 (address 4).

Does the ACH580 support Modbus TCP?

Not on its own: the embedded fieldbus is Modbus RTU on RS-485. Modbus TCP needs an FMBT-21 or FENA-21 option module, or an RTU-to-TCP gateway.

Why does Actual value 2 always read 0?

By default 58.29 EFB act2 type is Transparent and 58.32 EFB act2 transparent source is Not selected, so register 400006 carries nothing. Set a source or read the parameter directly, e.g. 01.07 Motor current at 420214.

Why won't my ACH580 start over Modbus?

Most often the start interlock: in the HVAC default 20.41 Start interlock 1 is DI4, and with DI4 open the drive shows warning AFEE and does not start. Also check the panel is in Auto, 20.01 is Embedded fieldbus and bit 10 of the control word is set (0x047F, not 0x000F).

How is the ACH580 frequency scaled on Modbus?

Reference 1 and Actual value 1 use 20000 = 46.02 Frequency scaling (50 or 60 Hz) in the default scalar control. Read 01.06 at 420212 in 32-bit instead and the value is simply Hz × 100.
